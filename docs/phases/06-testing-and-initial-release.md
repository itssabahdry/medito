# فاز ۶: آزمایش و انتشار نسخه اولیه

**حوزه مهارتی:** تست یکپارچه بخش‌های حساس، آماده‌سازی انتشار و Docker Compose.

## هدف

انتشار نسخه اولیه شامل فازهای ۱ تا ۵، با مسیرهای اصلی قابل استفاده و کنترل‌های حساس بررسی‌شده.

## ورودی و پیش‌نیاز

- [فاز ۵: نوبت‌دهی و نظرات و پیشنهادها](05-booking-reviews-and-ranking.md).
- امکانات پایه پیاده‌سازی‌شده و تست‌های همراه آن‌ها.

## مراحل کار

1. تست‌های حساس API را روی دیتابیس PostgreSQL جدا و داده ساختگی اجرا کن.
2. مسیرهای ثبت‌نام، تکمیل و بررسی مدارک، جست‌وجو، رزرو و نظر را یکپارچه بررسی کن.
3. در مرورگر، دسترسی نقش‌ها، رابط فارسی و راست‌به‌چپ، نمایش موبایل و مسیرهای اصلی را بررسی کن.
4. TypeScript و build تولیدی Next.js را بررسی کن و خطاهای بحرانی را پیش از انتشار برطرف کن.
5. Dockerfile و Compose را برای برنامه و PostgreSQL آماده کن؛ migration، healthcheck و volumeهای مستقل را در راه‌اندازی لحاظ کن.
6. متغیرهای محیطی و ساخت حساب مدیر را مستند کن؛ رمزها و مدارک وارد Git یا زمینه build نشوند.
7. پشتیبان‌گیری دیتابیس و مدارک و بازیابی روی محیط جدا را تعریف و در زیرساخت موجود بررسی کن.
8. انتشار آزمایشی با گروه محدود انجام بده و خطاها و محدودیت‌های تأییدنشده را ثبت کن.

## خروجی

- نسخه اولیه قابل اجرا با Docker Compose و راهنمای راه‌اندازی.
- گزارش نتیجه تست‌ها، مسیر پشتیبانی و دستورالعمل پشتیبان‌گیری و بازیابی.

## تست‌های حساس و معیار پذیرش

- مسیر ثبت‌نام تا رزرو و ثبت نظر، کنترل دسترسی مدارک، شروط تأیید و رزرو هم‌زمان بررسی شده باشند.
- درخواست از مبدأ خارجی رد شود؛ آدرس‌های محلی مجاز با پروتکل و پورت صحیح قابل استفاده باشند.
- build تولیدی موفق باشد و برنامه پس از آماده‌شدن دیتابیس بالا بیاید.
- داده‌ها پس از راه‌اندازی مجدد کانتینر باقی بمانند و حساب مدیر از مسیر مدیریتی قابل ایجاد باشد.
- نتیجه بازیابی و تحمل بار متناسب با انتشار اولیه، در حدی که واقعاً آزمایش شده، گزارش شود.
- نبود Docker Engine، دسترسی خارجی یا زیرساخت تست به‌صراحت ثبت شود؛ اجرای موفقِ انجام‌نشده گزارش نشود.
