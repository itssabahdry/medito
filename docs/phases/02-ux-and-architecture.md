# فاز ۲: طراحی تجربه کاربری و معماری

**حوزه مهارتی:** طراحی رابط فارسی و راست‌به‌چپ، معماری برنامه و مدل‌سازی داده.

## هدف

تبدیل نیازمندی‌ها به مسیرهای کاربری روشن و یک معماری ساده و قابل نگهداری با React، Next.js و PostgreSQL.

## ورودی و پیش‌نیاز

- [فاز ۱: تحلیل و تعیین محدوده](01-analysis-and-scope.md).
- نقش‌ها، معیارهای پذیرش و محدوده نسخه اولیه.

## مراحل کار

1. صفحه اصلی، ثبت‌نام و ورود، فهرست متخصصان، پروفایل، رزرو و پنل‌های نقش‌ها را طراحی کن.
2. رابط فارسی و راست‌به‌چپ باشد؛ نمایش موبایل، دسترسی با صفحه‌کلید و پیام‌های خطای روشن را در نظر بگیر.
3. تاریخ و ساعت نوبت‌ها را با تقویم فارسی و منطقه زمانی مشخص نمایش بده؛ زمان ورودی و زمان ذخیره‌شده مبهم نباشند.
4. از یک برنامه Next.js App Router با TypeScript و React استفاده کن؛ منطق سرور و API در همین پروژه باشند.
5. PostgreSQL، SQL مستقیم با `pg` و migrationهای نسخه‌دار را برای داده‌ها به کار ببر.
6. مدل کاربران، نشست‌ها، پروفایل‌ها، مدارک، سابقه بررسی، زمان‌های آزاد، نوبت‌ها و نظرات را تعریف کن.
7. مدارک را خارج از `public` و با دسترسی کنترل‌شده ذخیره کن؛ برای داده‌های پایدار دیتابیس و مدارک، volume مستقل در نظر بگیر.
8. سطح دسترسی را در سرور اعمال کن و ساختار را بدون سرویس، ORM یا لایه اضافیِ غیرضروری نگه دار.

## خروجی

- طرح صفحات و مسیر ثبت‌نام تا رزرو.
- ساختار فایل‌ها، مدل داده، قرارداد API و نقشه دسترسی نقش‌ها.
- تصمیم‌های مربوط به حریم خصوصی و نگهداری مدارک.

## بررسی و معیار پذیرش

- مسیر اصلی در موبایل و دسکتاپ قابل فهم باشد و اجزای ضروری دسترس‌پذیر باشند.
- تفاوت اطلاعات عمومی پروفایل و مدارک خصوصی در طراحی مشخص باشد.
- بررسی هویت، صلاحیت و وضعیت پرونده در رابط از هم قابل تشخیص باشند.
- معماری با فناوری‌ها و محدوده توافق‌شده سازگار باشد؛ کنترل‌های حساس در فازهای پیاده‌سازی تست می‌شوند.
