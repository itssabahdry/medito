# مدیتو — Medito

وب‌اپلیکیشن فارسی برای پیدا کردن متخصص سلامت روان، بررسی مدارک، رزرو نوبت، ثبت تجربه جلسه و مشاوره صوتی.

**ساختار:** React و Next.js App Router با TypeScript؛ PostgreSQL و SQL مستقیم با `pg`؛ بدون ORM، صف یا سرویس اضافی. فایل‌های تمرینی پوشه والد تغییر نکرده‌اند.

## امکانات

- ثبت‌نام مستقل مراجع و متخصص؛ پنل کاربر، متخصص و مدیر.
- بررسی جداگانه هویت و صلاحیت حرفه‌ای، بارگذاری خصوصی سه نوع مدرک، ثبت نتیجه استعلام و مصاحبه و سابقه تصمیم مدیر.
- پروفایل عمومی متخصص تأییدشده؛ فیلتر شهر، تخصص، نام و نوع جلسه.
- زمان‌بندی، رزرو، لغو، جابه‌جایی و ثبت انجام جلسه توسط متخصص؛ کنترل تداخل و رزرو هم‌زمان در PostgreSQL.
- یک نظر برای هر جلسه انجام‌شده، فقط توسط مراجع همان جلسه؛ رتبه‌بندی با میانگین تعدیل‌شده بر اساس تعداد نظرات.
- تماس صوتی WebRTC برای دو طرف نوبت، با مجوز زمانی و تب فعال؛ بدون ضبط صدا.
- راهنمای انتخاب با حفظ فیلترهای کاربر. اتصال اختیاری به OpenAI فقط حوزه درخواست را استخراج می‌کند؛ متخصصان همواره از دیتابیس انتخاب می‌شوند.

پرداخت، نسخه پزشکی، پرونده درمانی و تماس تصویری در محدوده این پروژه نیستند.

## اجرا با Docker Compose

پیش‌نیاز: Docker Engine و Compose؛ در ویندوز Docker Desktop با موتور Linux فعال. Node.js 22 برای ابزارهای محلی و ساخت فایل تنظیمات لازم است.

```powershell
cd 'D:\javascript course\medito'
node scripts/setup.mjs
docker compose config --quiet
docker compose up -d --build
docker compose exec web node scripts/create-admin.mjs
docker compose ps
```

سایت: **http://localhost:3000**. مشخصات مدیر در `.env` قرار دارند. اسکریپت setup برای دیتابیس و مدیر رمز تصادفی تولید می‌کند و فایل موجود را بازنویسی نمی‌کند. اگر Node نصب نیست، `.env.example` را به `.env` کپی کنید و رمزهای نمونه را عوض کنید؛ رمز PostgreSQL را از حروف و اعداد یا hex انتخاب کنید تا در URL معتبر باشد.

در اجرای محلی، آدرس‌های `localhost`، `127.0.0.1` و `[::1]` با پروتکل و پورت یکسان برای ثبت‌نام و سایر درخواست‌ها پذیرفته می‌شوند. برای انتشار روی دامنه یا IP شبکه، `APP_URL` را دقیقاً روی مبدأ عمومی برنامه تنظیم کنید؛ هدرهای Host و proxy به‌تنهایی مبدأ جدیدی را مجاز نمی‌کنند.

Compose شامل دو سرویس `web` و `db` است. دیتابیس روی شبکه داخلی کانتینرهاست و پورت عمومی ندارد. برنامه پس از healthcheck دیتابیس، migrationهای نسخه‌دار را اجرا می‌کند. داده‌های PostgreSQL و مدارک در دو volume مستقل نگهداری می‌شوند. برنامه داخل کانتینر با کاربر غیر root اجرا می‌شود.

```powershell
docker compose logs --tail=100 web
docker compose down
```

برای حفظ اطلاعات، از `down -v` استفاده نکنید. `DATABASE_URL` فایل `.env` برای توسعه محلی است؛ Compose آدرس داخلی `db:5432` را می‌سازد.

## اجرای محلی بدون Docker

```powershell
npm ci
node scripts/setup.mjs
npm run db:local
```

دستور آخر PostgreSQL واقعی را روی `127.0.0.1:55432` اجرا می‌کند و باید باز بماند. در ترمینال دوم:

```powershell
npm run db:migrate
npm run db:admin
npm run dev
```

در همین دستگاه یک نسخه portable از Node در پوشه هم‌سطح پروژه دانلود شده است. اگر `node` در PATH نیست، پیش از دستورات محلی در هر ترمینال این دستور را اجرا کنید:

```powershell
$env:Path = (Resolve-Path '..\.medito-tools\node-v22.23.3-win-x64').Path + ';' + $env:Path
```

اگر PostgreSQL موجود خودتان را استفاده می‌کنید، `DATABASE_URL` را تنظیم کنید؛ دیتابیس باید UTF-8 باشد و کاربر migration اجازه ساخت افزونه `btree_gist` را داشته باشد.

برای مشاهده پروفایل‌های ساختگی، `DEMO_DATA=true` و یک `DEMO_PASSWORD` حداقل ۱۲ کاراکتری را در `.env` تنظیم کنید، سپس:

```powershell
npm run db:seed
# یا داخل Docker:
docker compose exec web node scripts/seed.mjs
```

تمام پروفایل‌های seed برچسب «نمایشی» دارند و خدمات واقعی ارائه نمی‌کنند. نظر یا امتیاز ساختگی ایجاد نمی‌شود. حساب‌های آن‌ها مانند `sahar@demo.medito.local` با `DEMO_PASSWORD` وارد می‌شوند. داده نمایشی پیش‌فرض برای نصب جدید غیرفعال است؛ در محیط فعلی برای بازبینی رابط فعال شده است.

## فرایند بررسی متخصص

۱. متخصص ثبت‌نام و پروفایل حرفه‌ای را تکمیل می‌کند.
۲. مدرک هویتی، مجوز فعالیت و مدرک تحصیلی را بارگذاری می‌کند. PDF/JPEG/PNG تا ۵ مگابایت پذیرفته می‌شود؛ فایل‌ها خارج از `public` هستند و فقط مالک و مدیر دسترسی دارند.
۳. مدیر اصالت مدارک را با مرجع مربوط به عنوان حرفه‌ای بررسی می‌کند، مرجع و شماره پیگیری استعلام را ثبت می‌کند و مصاحبه انسانی انجام می‌دهد.
۴. تأیید نهایی فقط با هر سه مدرک و تمام مراحل بررسی امکان‌پذیر است. تغییر مدارک یا اطلاعات صلاحیت، پرونده را مجدداً در انتظار بررسی قرار می‌دهد.

**اتصال زنده به سامانه دولتی پیاده‌سازی نشده است:** دسترسی و قرارداد API رسمی ارائه نشده؛ این نسخه نتیجه بررسی رسمی انجام‌شده توسط کارشناس را ثبت می‌کند. هیچ نتیجه دولتی شبیه‌سازی یا تولید نمی‌شود.

## تماس صوتی و سرویس AI

ورود به اتاق تماس از ۱۰ دقیقه قبل از شروع تا ۱۵ دقیقه بعد از پایان نوبت ممکن است. نوبت باید صوتی و فعال و متخصص تأییدشده باشد. برای تست روی localhost، اتصال مستقیم دو مرورگر پشتیبانی می‌شود؛ برای کاربران روی شبکه‌های مختلف `TURN_URL`، `TURN_USERNAME` و `TURN_CREDENTIAL` را تنظیم کنید. انتشار اینترنتی به HTTPS برای دسترسی میکروفون نیاز دارد. سیگنالینگ داخل برنامه و PostgreSQL است؛ داده صوتی ذخیره نمی‌شود. خروج کاربر سیگنال‌های نشست او را پاک می‌کند و سیگنال‌های قدیمی‌تر از سه ساعت در ورود بعدی پاک می‌شوند.

برای AI، `OPENAI_API_KEY` و `OPENAI_MODEL` را با مدل قابل‌دسترسی دارای Structured Outputs تنظیم و سرویس web را مجدداً ایجاد کنید. متن فرم تنها با رضایت صریح کاربر ارسال می‌شود؛ مدارک، اطلاعات حساب، نوبت‌ها و فهرست متخصصان به مدل ارسال نمی‌شوند. درخواست از Responses API با `store:false` استفاده می‌کند؛ سیاست نگهداری ارائه‌دهنده نیز باید در انتشار عمومی بررسی شود. متن فرم در دیتابیس مدیتو ذخیره نمی‌شود.

بدون کلید و مدل، رابط صریحاً جست‌وجوی هدایت‌شده مبتنی بر کلمات کلیدی را نشان می‌دهد. اتصال واقعی AI در این محیط، به دلیل نبود کلید، اجرا نشده؛ اعتبارسنجی خروجی و محدودیت‌های آن با پاسخ‌های کنترل‌شده تست شده‌اند. این ابزار تشخیص یا درمان ارائه نمی‌کند و پیش از عرضه عمومی نیازمند ارزیابی متخصص حوزه است.

## تست

```powershell
npm test
npm run typecheck
npm run build
```

تست‌های API روی PostgreSQL واقعی و یک دیتابیس تصادفی و جدا اجرا می‌شوند و در پایان فقط همان دیتابیس را حذف می‌کنند. به دیتابیس برنامه دست نمی‌زنند. در صورت استفاده از سرور PostgreSQL موجود، `TEST_DATABASE_URL` را به حسابی با مجوز ساخت دیتابیس تنظیم کنید. اجرای embedded PostgreSQL با root پشتیبانی نمی‌شود؛ در این حالت از سرور تست جدا استفاده کنید.

تست مرورگر با Chrome نصب‌شده، در حالی که برنامه و دیتابیس محلی اجرا هستند:

```powershell
$env:PLAYWRIGHT_CHANNEL='chrome'
$env:E2E_ALLOW_DATABASE_WRITES='true'
npm run test:e2e
```

یا ابتدا `npx playwright install chromium` را اجرا کنید و `PLAYWRIGHT_CHANNEL` را تنظیم نکنید. تست مرورگر حساب‌ها، مدارک و نوبت‌های ساختگی مخصوص خودش را در دیتابیس محلی می‌سازد و پاک می‌کند؛ آن را روی محیط واقعی کاربران اجرا نکنید. تماس دوطرفه با میکروفون آزمایشی خود مرورگر تست می‌شود. برای آدرس متفاوت، `E2E_BASE_URL` و `APP_URL` را هماهنگ کنید.

تست‌ها شامل دسترسی مدارک، افزایش غیرمجاز نقش، CSRF، نشست، شروط تأیید، رزرو هم‌زمان، جابه‌جایی، نظرات، دسترسی و سیگنالینگ تماس، محدودیت خروجی AI، رابط موبایل و مسیر کامل ثبت‌نام و تأیید هستند.

## پشتیبان‌گیری و بازیابی

نمونه دستورات برای بکاپ دیتابیس و مدارک؛ آرشیوها حاوی اطلاعات خصوصی هستند و نباید وارد Git شوند:

```powershell
docker compose exec db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc -f /tmp/medito.dump'
docker compose cp db:/tmp/medito.dump ./medito.dump
docker compose exec web tar -czf /tmp/medito-documents.tar.gz -C /app/data documents
docker compose cp web:/tmp/medito-documents.tar.gz ./medito-documents.tar.gz
```

بازیابی را ابتدا روی نصب جداگانه و خالی بررسی کنید. بکاپ دیتابیس و مدارک باید متعلق به یک نقطه عملیاتی سازگار باشند؛ برای بکاپ عملیاتی، ایجاد یا تغییر مدارک را موقتاً متوقف کنید.

```powershell
docker compose cp ./medito.dump db:/tmp/medito.dump
docker compose stop web
docker compose exec db sh -c 'pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --clean --if-exists --no-owner /tmp/medito.dump'
docker compose start web
docker compose cp ./medito-documents.tar.gz web:/tmp/medito-documents.tar.gz
docker compose exec web tar -xzf /tmp/medito-documents.tar.gz -C /app/data
```

## وضعیت بررسی در محیط فعلی

- هر ۲۵ تست خودکار شامل کنترل مبدأ و مسیرهای حساس PostgreSQL پاس شده‌اند. ۷ تست مرورگر نسخه اولیه نیز روی خروجی standalone تولیدی پاس شده و شامل تماس صوتی واقعی بین دو نشست است؛ اصلاح ثبت‌نام روی هر دو آدرس محلی در Chrome و کانتینر فعال هم بررسی شد.
- بررسی TypeScript و ساخت production موفق بوده‌اند؛ مدارک و دیتابیس محلی در خروجی trace سرور قرار نمی‌گیرند. `.env` و `.next` خصوصی و خارج از Git هستند.
- `docker compose config --quiet` با Compose v5.6.0 موفق بوده است.
- در تحویل اولیه Docker Engine نصب نبود؛ اکنون build تصویر و اجرای `docker compose up -d --build --wait web` موفق بوده و هر دو سرویس سالم هستند.
- استعلام دولتی، AI خارجی، TURN عمومی و بازیابی داخل کانتینر بدون سرویس‌ها و دسترسی‌های واقعی تأیید نشده‌اند.

تاریخچه هر قابلیت در Git محلی است؛ ریپازیتوری ریموت ایجاد نشده است. ترتیب فازها و معیارهای پذیرش در [docs/plan.md](docs/plan.md) آمده است.
